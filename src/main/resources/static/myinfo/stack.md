# 2. 개발경험

## 2.1 머신러닝 기반 자동매매 프로그램

### 프로젝트 개요

Upbit 원화 마켓의 코인 데이터를 이용해 가격 방향을 예측하고, 예측 결과에 따라 매수·매도 판단을 수행하는 C# WinForms 기반 자동매매 프로그램을 개발했다.

### 주요 개발 내용

- Upbit API에서 코인 시세와 시간봉 데이터를 수집했다.
- 15분 봉을 기준으로 60분·240분 봉 데이터를 병합했다.
- 기술 지표와 시계열 데이터를 이용해 수백 개의 학습 피처를 구성했다.
- MLP, LightGBM, CNN1D 모델을 각각 학습하고 결과를 비교했다.
- 클래스 불균형 문제를 완화하기 위해 Focal Loss를 적용했다.
- Early Stopping과 SHAP 분석을 이용해 학습과 피처를 검증했다.
- Python에서 학습한 모델을 ONNX로 변환했다.
- C#의 ONNX Runtime에서 모델을 로드하고 실시간 추론을 수행했다.
- 모델 신호를 조합해 매수 조건을 판정했다.
- 최대 포지션 수, 최소 주문 금액, 익절·손절 및 가격 단위 처리 로직을 구현했다.
- WinForms에서 현재 시세, 예측 결과, 포지션 및 거래 상태를 표시했다.
- 다중 시간봉 누락, CNN 입력 순서, ONNX 변환 및 UI 크로스스레드 문제를 해결했다.

### 사용 기술

| 구분 | 기술 |
|---|---|
| 언어 | C#, Python |
| 데스크톱 | .NET 8, WinForms |
| 머신러닝 | LightGBM, MLP, CNN1D, PyTorch |
| 모델 배포 | ONNX, ONNX Runtime |
| 데이터 처리 | 시계열 처리, Feature Engineering, CSV |

## 2.2 알랴줌 서비스

### 프로젝트 개요

사용자가 원하는 브리핑을 등록하면 설정한 시간이나 조건에 따라 날씨, 코인, 환율, 뉴스 등의 데이터를 수집하고 Telegram으로 전달하는 개인 맞춤형 브리핑 서비스를 개발했다.

### 주요 개발 내용

- Java 21과 Spring Boot 3 기반으로 백엔드를 구현했다.
- 브리핑 정의, 입력·출력 스키마, 사용자 설정 및 조건을 DB 구조로 설계했다.
- 반복 브리핑과 조건 브리핑을 처리하는 스케줄러를 설계했다.
- 작업 실행을 위한 Job Queue와 외부 데이터 수집용 Collector Queue를 구성했다.
- 동일한 수집 요청을 중복 실행하지 않도록 input hash와 Unique 키를 사용했다.
- 외부 데이터에 TTL과 만료 시각을 적용하는 캐시 구조를 설계했다.
- 브리핑 검색, 테스트, 추가 및 실행을 위한 REST API를 구현했다.
- Telegram Bot API를 이용해 사용자에게 브리핑 메시지를 전송했다.
- Google과 Kakao OAuth2 로그인을 적용했다.
- Kakao Local API를 이용해 주소를 검색하고 위도·경도 데이터를 처리했다.
- MySQL을 이용해 사용자, 브리핑, 스케줄, 작업 큐, 캐시 및 메시지 데이터를 관리했다.
- Docker Compose로 Spring Boot, MySQL 및 웹 서버를 구성했다.
- AWS EC2 Ubuntu 서버에 서비스를 배포했다.
- Caddy와 Cloudflare를 이용해 도메인, Reverse Proxy 및 HTTPS를 구성했다.
- Logback 디렉터리, MySQL 초기화, DB read-only, 포트 충돌, Cloudflare 525 및 NXDOMAIN 등의 운영 오류를 분석했다.

## 2.3 스마트팜 자동제어 프로그램

### 프로젝트 개요

스마트팜의 온도, 습도 등 재배환경 데이터를 수집하고 작물별 적정 환경과 비교해 상태를 판단하며, 자동제어 명령을 생성하는 프로그램을 개발했다.

> 실제 하드웨어 장치를 직접 제어한 프로젝트는 아니다.  
> 센서 데이터 분석, 재배 상태 판단 및 제어 명령 생성·시뮬레이션 영역을 구현했다.

### 주요 개발 내용

- 스마트팜 시스템에서 센서와 재배환경 데이터를 수집했다.
- 온도, 습도 등 시계열 데이터를 저장하고 화면에 표시했다.
- 작물별 적정 생육환경 기준과 현재 환경 데이터를 비교했다.
- 현재 환경이 정상 범위인지, 조정이 필요한 상태인지 판단하는 로직을 구현했다.
- 판단 결과를 바탕으로 환기, 온도 및 습도 조절 등의 제어 명령을 생성했다.
- 실제 하드웨어 제어 대신 프로그램 내부에서 제어 결과와 상태 변화를 처리했다.
- GPT API를 이용해 센서 데이터와 재배 기준을 기반으로 판단 결과를 생성하는 기능을 적용했다.
- 데스크톱 UI에서 센서 상태, 판단 결과 및 제어 명령을 확인할 수 있도록 구성했다.
- 로컬 데이터베이스를 이용해 센서 데이터를 저장하고 조회했다.
- 로그인 세션과 HTTP 통신을 이용한 데이터 수집을 다뤘다.

### 사용 기술

| 구분 | 기술 |
|---|---|
| 언어 | C# |
| 데스크톱 | WinForms, .NET |
| 데이터 저장 | SQLite 또는 로컬 관계형 데이터 저장 |
| 데이터 처리 | 센서 데이터, 시계열 데이터, 환경 기준 비교 |
| AI 연동 | GPT API, 프롬프트 설계 |
| 통신 | HTTP 통신, 세션 처리 |
| 핵심 역량 | 스마트팜 환경 판단, 자동제어 명령 생성, 모니터링 UI |
| 제외 범위 | 실제 센서·모터·환풍기 등 하드웨어 직접 제어 |

## 2.4 GPT API 기반 템플릿·콘텐츠 생성 및 인스타그램 자동 업로드 프로그램

### 프로젝트 개요

미리 정의한 템플릿과 입력 정보를 기반으로 GPT API가 게시물 콘텐츠를 생성하고, 생성된 결과물을 인스타그램에 자동 업로드하는 콘텐츠 자동화 프로그램을 개발했다.

### 주요 개발 내용

- 사용자가 콘텐츠 주제와 필요한 값을 입력할 수 있도록 구성했다.
- 반복해서 사용할 수 있는 콘텐츠 템플릿 구조를 설계했다.
- 템플릿의 변수와 사용자 입력을 결합해 GPT API 요청을 생성했다.
- GPT API를 이용해 게시물 제목, 본문, 설명 및 콘텐츠 문구를 생성했다.
- 생성 결과를 템플릿에 적용해 최종 게시용 콘텐츠를 만들었다.
- 텍스트와 이미지 파일을 포함한 게시물 결과물을 저장하고 관리했다.
- 콘텐츠 생성부터 업로드까지 이어지는 자동화 흐름을 구현했다.
- 생성된 콘텐츠를 인스타그램에 자동 업로드하는 기능을 구현했다.
- 반복 작업을 줄이기 위해 템플릿 선택, 콘텐츠 생성 및 업로드 단계를 하나의 도구로 통합했다.
- API 오류, 생성 실패 및 업로드 실패를 고려한 처리 흐름을 구성했다.

### 사용 기술

| 구분 | 기술 |
|---|---|
| 생성형 AI | GPT API |
| AI 활용 | 프롬프트 설계, 콘텐츠 생성, 출력 형식 제어 |
| 자동화 | 템플릿 처리, 콘텐츠 생성, 파일 저장, SNS 업로드 |
| 외부 연동 | Instagram 업로드 연동 |
| 데이터 처리 | 템플릿 변수 치환, 텍스트 및 이미지 파일 처리 |
| 핵심 역량 | 생성형 AI 기반 콘텐츠 자동화, 외부 서비스 업로드 워크플로 |

> 이 프로젝트의 정확한 구현 언어, UI 프레임워크, 이미지 처리 라이브러리 및 인스타그램 연동 방식은 현재 정보에서 확정되지 않아 기술명으로 단정하지 않았다.
