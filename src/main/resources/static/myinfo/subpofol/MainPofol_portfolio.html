프로젝트 개요

단순 챗봇이 아니라, 관리 가능한 Markdown 문서와 추천 질문 DB를 결합한 개인 포트폴리오 질의응답 시스템입니다. 사용자 화면, 관리자 화면, AI 처리, 방문 통계, 알림 후처리를 하나의 Spring Boot 애플리케이션 안에 구성했습니다.

2-step 문서 선별 후 답변 생성으로 토큰 사용과 근거 범위를 제어
Async GPT 요청과 후처리를 분리해 다중 사용자 요청 처리
Admin 문서, 추천 질문, 질문 이력, 방문 통계를 관리하는 운영 화면

시스템 아키텍처

프론트엔드는 정적 React UMD 앱으로 제공하고, 백엔드는 Spring WebMVC, Spring Security, Spring Data JPA, Spring AI OpenAI 연동으로 구성했습니다.

AI 답변 생성 흐름

질문마다 전체 문서를 무조건 넣지 않고, 먼저 checklist 기반으로 관련 문서를 고릅니다. 이후 선택된 문서만 근거로 답변하게 해 환각 가능성과 불필요한 토큰 사용을 줄였습니다.

1

질문 수신

사용자 질문을 검증하고 progress 응답을 시작합니다.

2

목차 로드

checklist.md에서 참조 가능한 Markdown 파일 목록을 추출합니다.

3

문서 선택

OpenAI가 질문과 연관된 파일명을 JSON 형태로 반환합니다.

4

답변 생성

선택 문서 본문만 기반으로 한국어 답변을 생성합니다.

5

저장과 알림

질문 이력 저장과 Telegram 전송을 별도 executor에서 처리합니다.

주요 API와 기능

사용자 공개 API와 관리자 전용 API를 분리하고, 관리자 기능은 JWT 기반 stateless 인증으로 보호했습니다.

POST /api/ask

일반 질문 API입니다. CompletableFuture 응답으로 질문 처리를 AI executor에 위임합니다.

OpenAI Async DTO Response

POST /api/ask/progress

진행 상태를 application/x-ndjson으로 스트리밍하고, 완료 시 최종 답변을 반환합니다.

StreamingResponseBody NDJSON

GET /api/myinfo/recommended-questions

관리자가 등록한 추천 질문 목록과 저장된 답변을 사용자 화면에 제공합니다.

Recommended Q&A JPA

/api/admin/**

질문 이력, 추천 질문, Markdown 문서, 방문 통계 대시보드를 관리합니다.

JWT Admin CRUD

기술 스택

Java 21 기반 Spring Boot 애플리케이션에 정적 React 화면을 얹고, MySQL과 OpenAI API를 연결했습니다.

Backend

Java 21, Spring Boot 4.1, Spring WebMVC, Validation, Lombok

AI

Spring AI OpenAI starter, gpt-5-mini 기본 모델, 2단계 프롬프트 파이프라인

Persistence

Spring Data JPA, Hibernate, MySQL, JSON converter 기반 selectedFiles 저장

Frontend

정적 HTML, React 18 UMD, Babel standalone, CSS responsive layout

Security

Spring Security, JWT 인증 필터, 관리자 API 권한 분리

Operations

방문 통계, 관리자 대시보드, Telegram 알림, 비동기 후처리

설계 포인트

운영 가능한 작은 AI 서비스를 목표로, 지식 소스 관리, 비용 제어, 응답 추적, 관리자 운영 흐름을 함께 설계했습니다.

문서 기반 답변 제한

AI가 선택된 Markdown 내용만 근거로 답변하도록 프롬프트를 구성해, 포트폴리오 외 정보 추측을 줄였습니다.

요청 단위 비동기 처리

여러 클라이언트의 질문이 같은 컨트롤러 스레드를 오래 점유하지 않도록 AI executor를 분리했습니다.

후처리 장애 격리

질문 이력 저장과 Telegram 전송은 별도 async service에서 처리하고 실패 로그만 남겨 사용자 응답과 분리했습니다.

관리자 중심 운영

추천 질문과 문서를 관리자 화면에서 직접 관리해 배포 없이 지식 베이스와 노출 질문을 조정할 수 있습니다.

MainPofol 프로젝트 설명

MainPofol.md 내용을 포트폴리오 하단에 정리했습니다.

개발 계기

  • 구직자는 인사담당자가 어떤 정보를 원할지 생각 안하고 그냥 본인의 정보를 다 때려넣으면 되고
  • 인사담당자는 필요한것만 뽑아서 볼수 있으면 서로 편하겠다 싶어서 제작함
  • 겸사겸사 포트폴리오로도 씀

개발과정

  • 너무 간단한 프로젝트라 개발과정이라 할게 없음

발생했던 문제와 해결

  • 질문 입력 후 답변 받기까지 너무 오래걸림 -> 후처리작업등을 비동기로 빼서 답변 반환부터함
  • 그래도 오래걸림 GPT API 자체가 오래걸림 -> 임베딩모델을 쓰던가 임베딩API를 사용하면 되겠지만 현재는 그정도 성능이 필요없어 이대로 유지함

예상되는 문제와 예상해결방법

재사용성 미구현중

  • 질문 내용을 저장하고있으나 새로운 질문시 같은 질문에 대한 답변을 재사용하지않음
  • 질문 카테고리를 준비하고 GPT api 호출시 카테고리도 선택하게하여 카테고리와 함께 저장하고
  • GPT api 카테고리별 질문리스트와 함께 제공하여 같은 질문이 판단될시 해당 질문으로 답변하고 따로 저장하지않는 방법이 있음
  • 토큰 아까우면 카테고리 + 키워드로 입력토큰 줄일 수 있음
  • 임베딩작업으로 하면 성능,비용 더 줄일 수 있음

코덱스를 사용하여 만들었지만 제대로 이해하지 못한 부분

  • 프론트엔드는 최소한의 디자인 수정만 가능한 정도라 대부분 코덱스에게 맡김
  • 미들웨어 필터선에서 행해지는 시큐리티 작업은 큰 흐름만 알고있고 디테일한 작업은 학습이 부족한 상태임
  • 도커,AWS는 아직 미흡하여 조금 더 다뤄봐야함
